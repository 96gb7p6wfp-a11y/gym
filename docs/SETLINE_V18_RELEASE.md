## 已确认根因与修复

| 问题与代码证据 | V18 的处理 |
| --- | --- |
| 存储层只依赖初始版本时，两个首次打开的标签页可能都持有 `profileVersion: 0`；一个标签页创建真实记录后，另一个仍可能保存自己的初始资料。已加载的存储消失后也不应重新允许默认写入。见 [`storage.ts`](../src/storage.ts) 的 `read()`／`request()`。 | 跟踪是否已观察到存储及是否由其他标签页初始化。资料消失、损坏或外部初始化时拒绝写入并要求重新加载／审查恢复。真正首次安装仍可使用中性初始资料。 |

| 原方案更新直接替换模板，可能丢失兼容的器械、重量、组次或休息自定义。见 [`master-program-upgrade.ts`](../src/master-program-upgrade.ts)。 | 更新前审查差异，保留可匹配的配置；不确定的结构变化不能自动猜测。明确选择推荐结构才可继续，原周计划完整归档并先保存安全副本。 |
| 在减量状态编辑某一天，会保存已减量的 `customized:true` 日期草稿。随后改为 Green 或更新许可，移除的动作和组数仍不会自动回来。见 `App.jsx` 的 `workoutForDate()` 与 [`DayPrescriptionReset.tsx`](../src/DayPrescriptionReset.tsx)。 | 提供“Review this date’s reset”，先对比当前日期编辑与当前周处方；确认只移除对应日期／slot 草稿，保留周计划、模板、其他日期和历史。确认前重新核对存储版本及活动训练，先写安全副本。 |
| 方案表单草稿原来随对象引用或下一周期默认日期变化而重置，可能丢掉未保存编辑。见 [`VolleyballMasterProgram.tsx`](../src/VolleyballMasterProgram.tsx)。 | 按已保存字段的语义同步并合并外部变化，保留未保存编辑，包括跨午夜。未保存指导阻止 PWA 更新重载，直到保存或放弃。 |
| 准备课沿用完整课时长，减量来源不够清楚。见 [`training-prescription.ts`](../src/training-prescription.ts)。 | Today／预览／训练详情显示目的、工作组、强度、来源及调整原因；缩短时长明确标为估计。旧训练快照只解释保存内容，不用现在设置推断过去原因。 |

这些是仓库中确认并有回归覆盖的机制；尚不能证明它们分别发生在某一台 iPhone。不同 App 域名也有独立浏览器存储，另一个域名显示空资料不能直接证明原始资料被删除。

## 训练处方：改变与未改变

V18 不因训练感觉轻而增加基础周量，不覆盖个人自定义方案，也不自动补课。完整 V13.1 普通构建周的周三仍是：CMJ 3×2、Hack Squat 4×4–6、RDL 3×5–7、保加利亚分腿蹲 3×6／侧、坐姿提踵 3×8–12 和两项各 2 组的等长训练。

现有 V13.1 在重力量指导非 `cleared` 时，会把适用力量工作限制为最多两组、RPE 5、无预设额外负重；冲击指导未确认时移除最大跳／爆发内容。Yellow、周期减量、比赛周和日期自定义也会影响处方。V18 保留这些规则，明确区分 `unknown` 与 `restricted` 并解释实际变化，提供用户审查自己的指导与旧日期草稿的入口。没有从聊天自动设置任何人的许可。

训练科学依据、原处方与减量矩阵见 [训练审查](SETLINE_V18_TRAINING_REVIEW.md)。这些是通用原则和模板分析，不是对未读取个人日志的诊断。未记录的睡眠、球训或酸痛仍是未知，不视作零负荷或训练债务。

## 更快的记录

[`set-autofill.ts`](../src/set-autofill.ts) 在一次被接受的完成转换内，为同动作的下一个未完成组建议上一组重量与次数。例如记录 `60 kg × 8` 后，下组空白输入可建议 `60 × 8`，仍然是未完成草稿。Focus 和 Quick Log 共用同一训练记录及这次保存。

- 手动输入、主动清空、计划值、历史值及已有旧记录不被自动覆盖；可立即修改或使用上一训练表现。
- 可选 `inputSources` 仅记录输入来源，兼容旧备份；不复制完成状态、RIR、计时或测量成绩。
- 计时、距离、测量与准备性动作不会套用不适用的连续力量组建议。
- 沿用不可变组 ID、已消耗完成意图及幂等转换；重复请求不增加下一组、历史版本或休息计时器。
- Undo、单组纠正、历史编辑、刷新恢复和原休息截止时间保留。临时建议不是已完成训练。

界面保留 V17 的平静信息层级；事实性的已记录反馈缩短，二级说明可展开。Today 使用同一个主训练卡展示难度、时长和必要原因，未增加另一张仪表板。

## 设置、安全副本与恢复

Settings 延续 Training、Appearance & Sound、Data & Backup 三组；Training 展示当前方案及可独立保存的训练指导，My profile 使用现有个人输入界面。外观、音量等原值不因方案更新重置。

[`SetupRecovery.tsx`](../src/SetupRecovery.tsx) 与 [`setup-recovery.ts`](../src/setup-recovery.ts) 增加经过审查的局部恢复：

1. **设置恢复**：从有效备份选择资料、偏好、默认休息、外观／音效、营养输入和日程等设置；保留当前训练和记录。老备份缺少的新可选字段不强行恢复成默认。
2. **训练恢复**：恢复所选备份的周计划与方案配置；保留当前许可、日期编辑、模板、版本档案及全部训练记录。活动训练存在时阻止此操作。
3. 显示字段变化、计划内容、当前记录数量及精确网站 origin；预览本身不写入。
4. 确认时重新验证资料版本、恢复代次和预览；过期、取消或无效令牌不能覆盖数据。预览之后新增的合法训练／营养等记录继续保留。
5. 关键方案、指导、日期恢复操作，先把完整当前原始存储写入已有安全副本槽；副本失败即停止，主写入失败时保留原数据并回滚副本槽。
6. 局部恢复在事务开始前再次核对完整原始数据；另一标签页即使只新增训练或营养记录，也会使这次确认停止，要求重新审查，不用较早快照覆盖新记录。

安全副本仍保存在同一设备、同一网站存储中，不能替代外部文件备份或保证设备存储永不丢失。没有云同步，也没有跨域复制 `localStorage`。原完整备份恢复流程继续存在；它与局部恢复的范围不同。

推荐恢复步骤：先打开原先使用的 App 地址，在 Data & Backup 导出并保留有效备份；需要转移到另一域名／设备时，在目标地址选择备份，先审查范围与差异再确认。不要为恢复而清除网站数据、重装 PWA 或把新域名的中性资料当作原资料。

## PR、上线与回滚边界

本分支用于独立 V18 PR，实际 PR 与预览检查状态以 GitHub 为准。本轮不执行 main 合并或生产部署；PR #1 和 PR #5 未被合并或修改。用户提供的 Vercel 地址未能在当前环境中读取，无法确认其规范生产域名或当前代码版本，也没有访问设备里的设置。

这是增量兼容修改：保留 `setline.gym.v1`、存储 `schemaVersion: 1` 与备份 `version: 1`。新字段可选，读取旧数据不执行破坏性迁移；关键更改有原始安全副本。回退代码前应先保存外部备份，不将“回退代码”当作自动回退个人数据。完整恢复始终需要有效备份和显式确认。

## 简短使用路径

1. **Today**：查看今日训练、难度和时间，按唯一主操作开始；有调整时打开原因。
2. **Focus／Quick Log**：查看历史值或连续组建议，按需改值后完成；更正和 Undo 继续可用。
3. **You → Settings → Training**：确认当前方案、开始日期及本人保存的指导。更新方案先查看保留项和需确认项。
4. **View workout**：如果某日期保留旧减量编辑，打开该日期恢复审查；只在确认差异后使用当前周处方。
5. **Data & Backup**：检查当前网站地址；导出文件、审查局部恢复或使用原完整恢复，不清空存储寻找资料。
